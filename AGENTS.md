# Repository work

Preserve unrelated changes. Inspect Git status before editing. Do not change backend
execution authority or synthesize evidence to satisfy a UI. Use isolated local worlds
for mutations; saved demo runs are evidence, not disposable test fixtures.

## Client work

Read PRODUCT.md and DESIGN.md. The project-scoped skills in `.agents/skills` are
supporting instructions; explicit user requirements and correctness take precedence.
Use Impeccable for product/UX hierarchy and simplification, web-design-guidelines for
implementation review, ui-ux-pro-max for targeted references, and playwright for real
browser inspection. Read their relevant references explicitly if discovery is pending.
Automatic Impeccable hooks are not installed or approved. Use its manual detector.

Keep the two source modes and full-file component selector. Preserve every baseline
capability, backend guard, exact evidence label, and read-only historical workflow.
Use plain language and semantic controls. Include keyboard focus, reduced motion,
accessible text alternatives, loading/errors, and recoverable selection state.

Verify material UI changes with existing Node unit tests and Python pytest/Playwright
real-backend journeys. Add reusable browser regression tests for changed workflows.
Use axe plus manual keyboard/focus checks, desktop/laptop/narrow screenshots and
text enlargement; automated scans alone do not prove WCAG conformance. Record whether
real screen-reader testing occurred. Keep artifacts under `artifacts/` and compact
evidence/commands under `docs/client-rebuild/`. Never commit browser profiles/secrets.
